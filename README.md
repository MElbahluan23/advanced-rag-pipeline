# Qafela (قافلة) RAG

An end-to-end retrieval-augmented generation project. A local Llama model writes a synthetic knowledge base for **Qafela (قافلة)**, an Egyptian insurance-tech company in Cairo, then two RAG pipelines answer questions about it and are scored on the same test set.

The founder and CEO in the generated data is **Mohamed Elbahluan**.

**This data is fake.** Qafela, its employees, products, contracts, and test questions were generated for this project only. They are not a real company, and they are not real people or real insurance records.

Both pipelines live in the notebooks. There are no separate application modules. The retrieval, re-ranking, answering and scoring logic follows the course `week5` code (`implementation/`, `pro_implementation/`, `evaluation/eval.py`), written with LangChain instead of litellm.

`knowledge-base/`, `evaluation/`, `vector_db/`, and `preprocessed_db/` are generated, so git ignores them. Run the notebooks to recreate them.

## Quick start

### 1. Install

```bash
git clone git@github.com:MElbahluan23/insurellm-rag.git
cd insurellm-rag
uv sync
```

This creates `.venv/` with Python 3.12 and every dependency. To run the notebooks, register the kernel once and pick **Python (insurellm-rag)** in the kernel picker:

```bash
uv run python -m ipykernel install --user --name insurellm-rag --display-name "Python (insurellm-rag)"
```

Add a package with `uv add <package>`. `requirements.txt` is kept for plain `pip` users.

### 2. Start Ollama for notebook 01

```bash
ollama pull llama3.2
ollama serve
```

Notebook 01 calls Llama locally. It does not need an API key. The simple pipeline in notebook 02 also answers with `llama3.2` through Ollama, so keep `ollama serve` running.

### 3. Add API keys for notebook 02

```bash
cp .env.example .env
```

Put `OPENAI_API_KEY` and `GROQ_API_KEY` in `.env`. Embeddings run locally with HuggingFace `all-MiniLM-L6-v2` (384 dimensions, no key needed; the model downloads on first use). The simple pipeline answers with Ollama `llama3.2`. OpenAI `gpt-4.1-nano` chunks documents for the pro pipeline and judges the answers. The pro pipeline rewrites, re-ranks and answers with LangChain's `ChatGroq`.

### 4. Run notebook 01

Open `notebooks/01_build_synthetic_data.ipynb` and run it from the top.

Steps 4–7 write the knowledge base:

| Folder | Files |
|---|---|
| `company/` | 4 pages: about, overview, culture, careers |
| `employees/` | 32 Egyptian employee profiles |
| `products/` | 8 product sheets |
| `contracts/` | 16 contracts with Egyptian insurers, amounts in EGP. Each client is matched to the product it buys, such as an auto insurer with Carllm. |

Step 10 reads those markdown files and writes `evaluation/tests.jsonl`. Each line is one question whose keywords and reference answer come from that file. A question is kept only when every keyword appears in the source document.

Re-running is safe by default. `OVERWRITE = False` skips files that already exist, and `REBUILD_TESTS = False` keeps an existing `tests.jsonl`. Set either to `True` to regenerate. The LLM calls retry up to 3 times and warn if an answer is cut off by `MAX_TOKENS`.

### 5. Run notebook 02

Open `notebooks/02_rag_implementations.ipynb` and run it in order.

1. **Simple RAG** splits documents on a fixed size, embeds them, and answers from one vector search.
2. **Pro RAG** asks the model to chunk each document, rewrites the question, searches twice, and re-ranks the chunks.
3. **Compare Simple vs Pro** loads `evaluation/tests.jsonl` and scores both pipelines.

`MAX_TESTS` at the bottom of notebook 02 defaults to 5. Raise it when you want the full file.

Embedding and LLM chunking take time (and chunking costs API calls), so they only run when the database is missing or empty. Set `REBUILD = True` in the config cell (Step 1.1) to rebuild both `vector_db/` and `preprocessed_db/`, for example after you change the knowledge base.

## How a test line is shaped

Each line has this shape (the `TestQuestion` model in both notebooks):

```json
{"question": "Who is the CEO of Qafela?", "keywords": ["Mohamed", "Elbahluan", "CEO"], "reference_answer": "Mohamed Elbahluan is the Co-Founder and CEO of Qafela.", "category": "direct_fact"}
```

The generator aims for this mix of 150 questions: 70 `direct_fact`, 20 `temporal`, 20 `spanning`, 10 `comparative`, 10 `numerical`, 10 `relationship`, and 10 `holistic`.

---

## How the comparison is scored

The last cell of notebook 02 runs both pipelines on each test question and scores them.

| Score | What it measures |
|---|---|
| Retrieval MRR | How high the first chunk containing each keyword is ranked |
| Retrieval nDCG | Whether relevant chunks sit near the top |
| Keyword coverage | Share of keywords found in the retrieved chunks |
| Accuracy | Judge score, 1–5, against the reference answer |
| Completeness | Judge score, 1–5, for covering the reference answer |
| Relevance | Judge score, 1–5, for answering only the question |

---

## Simple vs pro

| | Simple | Pro |
|---|---|---|
| Chunking | Fixed size, 500 characters | Model writes a headline, summary, and original text |
| Vector store | LangChain Chroma, top 10 chunks | Raw Chroma client, 20 chunks then top 10 after re-ranking |
| Query | The user question as written | Model rewrites the question from the conversation |
| Search | One search | Original question and rewritten question, merged |
| Ranking | Vector similarity | Model re-ranks the chunks |
| Retries | None | Exponential backoff, up to 5 attempts |

## Change the company

Edit `COMPANY` and `CLIENT_POOL` in notebook 01, then delete the old files in `knowledge-base/` (or set `OVERWRITE = True`) and rerun the notebook. Each client in `CLIENT_POOL` has a `"product"` key, and you need at least `clients_per_product` clients per product. Then set `REBUILD = True` in notebook 02 and `REBUILD_TESTS = True` in notebook 01.

```python
COMPANY = {
    "name": "Qafela (قافلة)",
    "founded": 2015,
    "founder": "Mohamed Elbahluan",
    "hq": "Cairo, Egypt",
    "employee_roles": [...],   # 32 people
    "clients_per_product": 2,  # 8 products x 2 = 16 contracts
}
```

To switch the local model:

```python
MODEL_ID = "llama3.2"
# MODEL_ID = "mistral"
# MODEL_ID = "qwen2.5:14b"
```
